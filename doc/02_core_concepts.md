# 2. 中心概念の定義

## 2.1 ロジック（Logic）

このツールが管理する1つの「判断フロー」の単位。  
1つのロジックは、**複数のテーブルが有向非巡回グラフ（DAG）を形成したもの**として定義される。

- DAGにはエントリーテーブルが1つ存在し、評価はそこから開始される。
- エントリーテーブルから到達可能なすべてのテーブルがロジックの構成要素である。
- ユーザーが操作・保存・共有する基本単位はロジックである。

## 2.2 テーブル（Table）

ロジックの構成要素となる個別の決定テーブル。

- 1つのテーブルは、フィールド列（条件列）の集合と、ルール行の集合で構成される。
- 1つのテーブルは独立した「問い」を扱う。条件が増えて複雑になった場合は、テーブルを分割して継続参照で連鎖させることを推奨する。
- 同一のテーブルが、複数の親テーブルから継続参照されることは許可する（DAGの性質上、問題ない）。

## 2.3 ルール行（Rule / Row）

テーブル内の1行。ルート→終端への1パスを表す。

- 複数の条件セルと、1つの結論セルで構成される。
- 行は上から順に評価され、**全条件セルが一致した最初の行**が採用される（first-matchセマンティクス）。
- 結論セルは「終端結論」または「継続参照」のいずれかである（後述）。

## 2.4 条件セル（Condition Cell）

ルール行とフィールド列の交点に配置される条件。

- 1つの条件セルは「フィールドの値がこの演算子と値を満たすか」を表す。
- 条件が設定されていないセルは**ワイルドカード**（任意の値に一致）として機能する。

## 2.5 結論セル（Conclusion Cell）

ルール行の結論を保持するセル。以下の2種類のいずれかの値を持つ。

| 種別                     | 意味                                                            | 表示例                                             |
| ------------------------ | --------------------------------------------------------------- | -------------------------------------------------- |
| **終端結論（Terminal）** | このロジックの最終的な出力。**1つ以上の出力列**に値を設定できる | `対応手順: "解約金を案内する"`, `転送先: "03-..."` |
| **継続参照（Continue）** | 評価を別のテーブルへ引き継ぐ                                    | `→ テーブルB`                                      |

継続参照の場合、ユーザーが最初に指定した**入力コンテキスト（フィールド値のマップ）がそのまま次のテーブルに渡される**。次のテーブルは同じ入力コンテキストを使って評価を継続する。テーブルAの「評価結果」が渡されるのではなく、「評価の入力」が引き継がれる点に注意。

## 2.6 フィールド（Field）

条件列に割り当てるデータ項目の定義。名前と型を持つ。  
ロジック全体で共有されるマスターレコードであり、複数のテーブルで同一フィールドを参照できる。
