# 8. UI設計

## 8.1 全体レイアウト

ヘッダー＋2ペイン＋ボトムドロワーで構成する。フィールド定義は左ペインのアコーディオンセクションへ集約し、評価パネルはボトムドロワーとして折りたたみ可能とする。

```
┌─────────────────────────────────────────────────────────────────┐
│  [LEVERIE ロゴ]                              [EN/JP] [新][⬆][⬇] │ ← ヘッダー（コンパクト・アイコンのみ）
├─────────────────┬───────────────────────────────────────────────┤
│  左ペイン       │  右ペイン（テーブルエディタ）                  │
│                │                                               │
│  ロジック名     │  [テーブル名] [▶入口バッジ] [テーブル|フローチャート] │
│  [ロジック名]   │                                               │
│  ─────────     │  [ディシジョンテーブル / フローチャート]        │
│  ▼テーブル関係図 │                                               │
│   [DAGグラフ]   │  [＋条件列を追加] [＋行を追加]                  │
│                │                                               │
│  ▼テーブル一覧  │  ⚠️ カバレッジギャップ警告（あれば）            │
│   [テーブルA]  │                                               │
│   [テーブルB]  │                                               │
│   [+テーブル追加]│                                              │
│                │                                               │
│  ▼フィールド定義 [⬆][⬇]                                         │
│   [field 一覧]  │                                               │
│   [追加フォーム] │                                               │
├─────────────────┴───────────────────────────────────────────────┤
│  ▲ 評価パネル（クリックで開閉）                                    │ ← ボトムドロワー
│   [単一評価] [バッチ評価]                                          │
│   [入力フォーム / トレース / バッチ結果]                          │
└─────────────────────────────────────────────────────────────────┘
```

### ヘッダーの役割

ヘッダーはツール全体に関わる要素のみを配置し、コンパクト（高さ約 48px）に保つ。アクションは**アイコンのみ＋ツールチップ**で表示する。

| 要素                 | 説明                                                    |
| -------------------- | ------------------------------------------------------- |
| LEVERIE ロゴ         | 左端に常に表示（[src/assets/logo.svg](../src/assets/logo.svg)） |
| 言語セレクト         | `EN` / `日本語` を切り替える。選択値は `localStorage` キー `leverie-lang` に保存 |
| 新規作成ボタン       | 現在のロジックを閉じて初期状態で新しいロジックを作成する。確認ダイアログを表示してから実行する |
| インポートボタン     | JSONファイルを読み込む（§8.6 参照） |
| エクスポートボタン   | 現在のロジックを `<ロジック名>.json` としてダウンロード |

## 8.2 左ペイン

左ペインは上から「ロジック名セクション → アコーディオン群（テーブル関係図 / テーブル一覧 / フィールド定義）」の順に構成する。

### ロジック名セクション

左ペインの最上部に**固定表示**（スクロール対象外）するセクション。現在編集中のロジックを示す。

- 「ロジック名」というラベルを小さく表示し、その下にロジック名を表示する
- ロジック名はクリックするとインライン編集が可能（Enterで確定、Escapeでキャンセル）
- アコーディオン群とは `border-b` で区切られた独立したセクションとして視覚的に区別する

### アコーディオン群

ロジック名の下に**アコーディオン形式**の3セクションを縦に並べる。各セクションは個別に折りたたみ可能で、開閉状態は `localStorage` キー `leverie-ui-prefs` に永続化する（リロード後も復元）。

| セクション | キー | 内容 |
| --- | --- | --- |
| テーブル関係図 | `dag` | テーブル間の依存関係を有向グラフで表示（[07_visualization.md](07_visualization.md) §7.2 参照） |
| テーブル一覧 | `tables` | ロジック内の全テーブルのリスト。クリックで右ペインに表示を切り替える。エントリーテーブルには「▶」マークを付ける。「＋ テーブルを追加」ボタンを末尾に配置 |
| フィールド定義 | `fields` | ロジック全体で共有するフィールドの追加・編集・削除UI（§8.3 参照）。ヘッダー右側に**フィールド定義 JSON のインポート/エクスポート**用のアイコンを配置 |

初期状態では3セクションすべて開いた状態とする。

## 8.3 フィールド定義セクション（左ペイン内）

ロジック全体で共有するフィールド定義の管理UI。**右ペインではなく左ペインのアコーディオン**として配置する（複数テーブルを横断するマスターデータであるため、テーブル個別エディタとは独立した位置とする）。

### 操作仕様

| 操作                                    | UI                                                                                                                             |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| フィールドの追加                        | セクション最下部の「フィールド名」入力＋型ドロップダウン＋「＋」ボタン。Enterキーでも確定 |
| 詳細表示の展開                          | 各フィールド行のシェブロン（`▶ / ▼`）をクリックで詳細編集パネルを開く |
| フィールド名の変更                      | 詳細パネル内のインライン編集（Enterで確定、Escapeでキャンセル） |
| フィールドの型変更                      | 詳細パネル内の型ドロップダウンを変更。確認ダイアログを経て実行（[03_data_model.md §3.2](03_data_model.md) 参照） |
| `enumValues` の値の追加・削除・名称変更 | enum型フィールドの詳細パネルに表示される選択肢リスト上でインライン編集。名称変更は確定と同時にロジック全体の条件セルに自動反映 |
| フィールドの削除                        | フィールド行にホバー時に表示されるゴミ箱アイコン。参照中の条件列がある場合は拒否 |

### フィールド定義 JSON のインポート / エクスポート

セクションヘッダー右端に⬆（インポート）と⬇（エクスポート）の小さなアイコンを配置し、**フィールド定義のみ**を別ファイルとしてやり取りできるようにする（ロジック全体の JSON とは独立）。

ファイル形式:

```json
{
  "version": "1",
  "fields": [
    { "name": "顧客種別", "type": "enum", "enumValues": ["法人", "個人"] },
    { "name": "申請金額", "type": "number" }
  ]
}
```

| 操作 | 挙動 |
| --- | --- |
| エクスポート | 現在のロジックの `fieldDefs` を上記の形式でダウンロード。ファイル名は `<ロジック名>_fields.json` |
| インポート | ファイルを読み込み、現在のロジックに**追加**する（既存フィールドは上書きしない）。同名フィールドは**スキップ**し、追加件数とスキップしたフィールド名をトーストで通知する |

異なるロジック間で共通のフィールドカタログを使い回すユースケースを想定している。

## 8.4 右ペイン（テーブルエディタ）

右ペインは選択中のテーブルのエディタのみを表示する（フィールド定義パネルは左ペインへ移動済み）。

### テーブルヘッダー

| 要素 | 説明 |
| --- | --- |
| テーブル名 | インライン編集可能（クリックで編集モード、Enter確定 / Escapeキャンセル） |
| エントリーバッジ | エントリーテーブルの場合「▶ 入口」を表示 |
| 入口に設定ボタン | エントリー以外のテーブルの場合に表示。クリックで `entryTableId` を変更 |
| ビュー切替タブ | 「テーブル / フローチャート」（[07_visualization.md §7.1](07_visualization.md) 参照）。フローチャートタブにはカバレッジギャップ件数のバッジを表示 |

### ツールバー

- テーブル下部のツールバーに「＋ 条件列を追加」「＋ 行を追加」ボタンを並べて配置する
- 結論列ヘッダーには⚙アイコン（出力列を管理）を配置する
- 「品質チェック（カバレッジ計算）」は明示的なボタンを設けず、`enum`/`bool` で構成されたテーブルでは自動計算してフローチャートのファントムノードとバナー警告に反映する

### 結論セルの変更

- 現行の単一テキスト入力から、**終端 / 継続の種別選択UI**に変更する
- 終端結論の場合、テーブルに定義された出力列（`outputCols`）ごとに入力欄を表示する

### 結論種別の切り替え挙動

「○ 終端結論 ○ 継続参照」を切り替えた際、切り替え前のデータは**破棄する**（復元しない）。種別切り替えは不可逆操作とする。

| 切り替えパターン | 条件                                 | 挙動                                                                                                                             |
| ---------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 終端 → 継続      | 出力列にひとつでも値が入力済みの場合 | 確認ダイアログを表示:「継続参照に切り替えると、入力済みの出力値がすべて削除されます。続けますか？」→「切り替える」「キャンセル」 |
| 終端 → 継続      | 出力列がすべて未入力の場合           | 確認なしで即切り替え                                                                                                             |
| 継続 → 終端      | テーブルの選択有無に関わらず         | 確認なしで即切り替え（`tableId` は破棄。出力列の入力欄は空の状態で表示）                                                         |

この設計により、実装がシンプルになり（UIの「戻す」パスが不要）、ユーザーも「切り替えは上書き操作」として一貫して理解できる。

```
結論エリアのUI（終端結論の場合）:

  [ ○ 終端結論  ○ 継続参照 ]

  ┌─────────────────────────────────────────┐
  │ 対応手順                                 │  ← outputCols[0].name
  │ [ テキストエリア（複数行入力可） ]          │
  ├─────────────────────────────────────────┤
  │ 転送先電話番号                            │  ← outputCols[1].name
  │ [ テキスト入力 ]                          │
  ├─────────────────────────────────────────┤
  │ 備考                                     │  ← outputCols[2].name
  │ [ テキスト入力 ]                          │
  └─────────────────────────────────────────┘

結論エリアのUI（継続参照の場合）:

  [ ○ 終端結論  ○ 継続参照 ]

  [ テーブル選択ドロップダウン ▼ ]
  （循環参照となるテーブルはdisabledで表示）
```

### 出力列の管理UI（テーブルレベル）

テーブルエディタの結論列ヘッダーに⚙アイコンを設置し、`outputCols` の追加・名前変更・削除ができるパネルを開く。出力列の削除挙動は [06_quality_checks.md §6.7](06_quality_checks.md) の必須制約に従う。

- 出力列が2件以上あり削除対象に値が設定されている行がある場合: モーダルで影響件数を確認してから削除（対象行の出力値は削除される）
- 出力列が2件以上あり削除対象に値が設定されている行がない場合: 確認なしで即削除
- 出力列が1件のみの場合: 削除ボタンを `disabled` にして「出力列は最低1つ必要です」とツールチップ表示（削除不可）

### エントリーテーブルの変更フロー

「入口に設定」ボタンをクリックした場合、即座に `entryTableId` を更新する。

### 品質チェック表示

- テーブル内の警告（重複行・到達不能行）は、該当行の左端に警告バッジを表示する
- バッジにホバーすると警告内容を説明するツールチップを表示する
- カバレッジギャップ（§6.8）はテーブルビュー下部の黄色バナーと、フローチャートビューのファントムノードで可視化する

### 条件セルエディタのUX

条件セルをクリックすると、セルの近傍にポップアップパネルが開く。ポップアップ内に演算子ドロップダウンと値入力UIを配置する（`between` の2値入力や `in` のタグ入力など複数値の入力に対応するため、セル内ではなくポップアップを使用する）。

- セル本体には現在の条件の概要テキストを常に表示する（例: `>= 100`、`法人, 個人`、`（条件なし）`）
- Escapeキーまたはポップアップ外クリックでポップアップを閉じる
- ワイルドカード（条件なし）の状態は `（条件なし）` と表示し、ポップアップで条件を設定するとセル概要に反映される

**ワイルドカードの内部表現:**

ワイルドカード状態とは `row.cells` のマップにそのセルのキー（`colId`）が存在しない状態である。ユーザーがポップアップで「条件なし」を明示的に選択した場合は、`row.cells` からそのキーを削除することでワイルドカード化する（空のセルオブジェクトを格納するのではなく、キーを削除する）。

### 行の並び替えUX

行の評価順序（first-matchセマンティクス）は結果に直接影響するため、行の並び替えを2つの方法で提供する。

- **ドラッグ&ドロップ**: 行左端に表示されるドラッグハンドルアイコンをつかんで任意の位置に移動する
- **上下矢印ボタン**: 行をホバーしたときに「1つ上へ」「1つ下へ」ボタンを表示する

行の並び替えは first-match セマンティクスに直接影響するため、移動が確定した瞬間に §6.2（重複ルール）・§6.3（到達不能行）の警告をリアルタイムで再計算して表示を更新する。

## 8.5 評価パネル（ボトムドロワー）

評価パネルはアプリ画面の**下端に常駐するドロワー**として配置する（左右ペインの下に渡る形）。

- ドロワーヘッダーをクリックすると開閉する。開閉状態は `localStorage` キー `leverie-ui-prefs` に永続化する
- 開いたときの高さは画面の 60vh
- ヘッダーには「評価パネル」というタイトルとシェブロン（▲/▼）を表示する
- パネル内には「単一評価」「バッチ評価」のタブを配置する（[09_debug_trace.md](09_debug_trace.md)・[10_batch_evaluation.md](10_batch_evaluation.md) 参照）
- タブの切り替えはそれぞれの状態（入力値・結果）に影響しない

## 8.6 ロジックの保存・共有

| 機能                       | 説明                                                                                                                                                              |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| JSONエクスポート           | ロジック全体を1つのJSONファイルとしてダウンロード。ファイル名は `<ロジック名>.json`（ロジック名が空の場合は `logic.json`、ファイル名に使えない文字は `_` に置換） |
| JSONインポート             | エクスポートしたJSONファイルを読み込む（§8.7参照）                                                                                                                |
| フィールド定義 JSON のインポート/エクスポート | 左ペイン「フィールド定義」セクションのヘッダーから操作（§8.3 参照） |
| ローカルストレージ自動保存 | 編集のたびに自動保存し、リロードで復元できる。キー名は `decision-table-editor-v2` |
| URL シェア                 | ロジック全体をBase64エンコードしてURLに埋め込む（将来対応）                                                                                                       |

## 8.7 新規ロジック作成時の初期状態

「新規作成」操作でロジックを作成した場合、以下の初期状態を生成する。

| 要素           | 初期値                                     |
| -------------- | ------------------------------------------ |
| ロジック名     | 「新しいロジック」 / "New Logic"（言語設定により）|
| テーブル       | 1件（ID: `"t1"`、名前: 「テーブル1」/ "Table 1"）|
| `entryTableId` | `"t1"`                                     |
| 出力列         | 1件（ID: `"oc1"`、名前: 「結果」/ "Result"）|
| フィールド     | 0件（ユーザーが追加する）                  |
| ルール行       | 0件（ユーザーが追加する）                  |
| `nField`       | `1`（次のフィールドは `f1`）               |
| `nTable`       | `2`（`t1` 生成済みのため次は `t2`）        |
| `nCol`         | `1`（条件列は0件だが次の採番は `c1` から） |
| `nOCol`        | `2`（`oc1` 生成済みのため次は `oc2`）      |
| `nRow`         | `1`（次のルール行は `r1` から）            |

**カウンターの採番設計（1ベース）:**

すべてのIDは `"f1"`, `"c1"`, `"r1"`, `"t1"`, `"oc1"` のように **1から始まる**（0ベースではない）。これはIDを人間が読んだときに「1番目」「2番目」と直感的に対応しやすくするためである。カウンターは「次に採番するIDの数値部分」を表すため、初期値は以下の意味を持つ。

- 対応するオブジェクトが**0件の状態** → カウンターは `1`（次が最初の `1`番）
- 対応するオブジェクトが**N件存在する状態** → カウンターは `N + 1`（次は `N+1` 番）

`nCol = 1` は「条件列がまだ1件も存在しないため、最初に追加した条件列が `c1` になる」という意味であり、`c0` は使用しない設計となっている。

**既存ロジックへのテーブル追加時の初期状態:**

左ペイン「テーブル一覧」の「＋ テーブルを追加」ボタンで既存ロジックに新しいテーブルを追加した場合、以下の初期状態を生成する。

| 要素           | 初期値                                                                                                                                                                                                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`           | `"t{nTable}"` を採番し、`nTable` を +1 する                                                                                                                                                                                                                                   |
| `name`         | 「テーブル{nTable採番前の値}」（例: 現在 `nTable = 3` なら「テーブル3」）。同名のテーブルが既に存在する場合は末尾に番号を付けて自動で一意にする（例:「テーブル3 (2)」）。これは自動生成名のための特例であり、手動のインライン編集で重複名を入力した場合は拒否する |
| `outputCols`   | 1件（`id: "oc{nOCol}"`、`name: "結果" / "Result"`）を自動生成し、`nOCol` を +1 する                                                                                                                                                                                            |
| `cols`         | 0件                                                                                                                                                                                                                                                                           |
| `rows`         | 0件                                                                                                                                                                                                                                                                           |
| `entryTableId` | **変更しない**（追加操作でエントリーテーブルは切り替わらない）                                                                                                                                                                                                                |

追加したテーブルはDAGグラフとテーブルリストに即座に追加され、孤立状態（どこからも参照されていない）として表示される。

## 8.8 アプリ起動時の状態復元とインポート時の挙動

### 起動時の状態復元

起動時は以下の優先順序でローカルストレージを探索する。

| 優先順 | キー名                     | 処理                     |
| ------ | -------------------------- | ------------------------ |
| 1      | `decision-table-editor-v2` | フォーマットとして復元   |
| 2      | 上記が存在しない           | §8.7の初期状態で新規起動 |

加えて、UI設定（左ペインアコーディオン開閉・評価ドロワー開閉）は `leverie-ui-prefs`、言語設定は `leverie-lang` をそれぞれ復元する。

- データが破損していた場合は新規状態で起動する（破損データは無視）
- ローカルストレージの容量超過時は「データの自動保存に失敗しました。『エクスポート』からファイルに保存してください。」というトーストを表示する

### インポート時の確認

作業中のロジックがある状態でJSONをインポートする際は、ファイル選択直後にバリデーションを行い、成功した時点で**現在のロジックを置き換え**、評価結果とバッチ結果をクリアする。

### インポートバリデーションとエラー表示

| エラー種別                                                                     | 修復戦略                                                                              | ユーザーへの表示                                                                                 |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| JSONの構文エラー                                                               | 修復不可。読み込みを中止                                                              | 「JSONのパースに失敗しました。」                                                                 |
| スキーマ不整合（必須フィールド欠落など）                                       | 修復不可。読み込みを中止                                                              | 「JSONの形式が正しくありません。{詳細メッセージ}」                                              |
| 継続参照先のテーブルIDが存在しない                                             | その行の結論を `{ type: "terminal", outputs: {} }` にリセット                         | 「インポート時に自動修復を行いました: 参照先が見つからない継続参照をリセットしました。」 |
| テーブルの出力列が0件                                                          | デフォルト出力列を自動追加（下記の採番ルールを参照）                                  | 「インポート時に自動修復を行いました: 出力列が未定義のテーブルに「結果」列を追加しました。」 |
| `nOCol`・`nCol`・`nRow`・`nField`・`nTable` などのカウンターが実際のIDの最大値より小さい | 各カウンターを `実際の最大値 + 1` に上書きして修復                                    | （ユーザーへの表示なし — サイレント修復）                                                        |

**インポート修復時の出力列ID採番ルール:**

出力列が0件のテーブルにデフォルト出力列を自動追加する際は、以下の手順でIDを決定する。

1. インポートデータ内のすべての `outputCols` に存在するIDから数値部分を抽出し、最大値を求める（例: `oc1`, `oc3`, `oc5` → 最大値は `5`）
2. 自動追加する出力列のIDを `"oc{最大値 + 1}"` とする（上記の例では `oc6`）
3. ルートオブジェクトの `nOCol` を `最大値 + 1` に更新する

インポート後は `nOCol` が正しい値に整合されているため、以降の通常採番は正しく動作する。`nCol`・`nRow`・`nField`・`nTable` についても同様に、対応するID群の実際の最大値 + 1 に上書きしてカウンターを修復する。

- 修復不可の場合はトーストでエラーを表示し、現在のロジックは維持する
- 修復成功の場合はロジックを読み込んだ後にトーストで修復内容を知らせる
- インポート成功時は評価パネルの結果（`evalResult`）とバッチ結果（`batchResults`）をリセットする（古いロジックに基づく結果が残るのを防ぐため）

## 8.9 多言語対応（i18n）

UI文言は **EN（英語） / JA（日本語）** の2言語をサポートする。

- 切り替えはヘッダー右側の言語セレクトから行う
- 翻訳キーは [src/i18n/translations.ts](../src/i18n/translations.ts) に集約し、`useT()` フック経由で参照する
- 選択言語は `localStorage` キー `leverie-lang` に永続化する。初期値は `en`
- ストア層から発生するエラーメッセージや初期テキスト（「新しいロジック」「テーブル1」「結果」など）も翻訳テーブルから取得する。`getT()` ヘルパーで React 外からも現行言語の翻訳セットを取得できる

新しい文言を追加する際は **EN / JA 両方の翻訳キーを必ず追加**すること（型レベルで強制される）。
