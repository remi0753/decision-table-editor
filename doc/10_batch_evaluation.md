# 10. バッチ評価（CSVインポート）

## 10.1 概要

評価パネルに**バッチ評価モード**を追加する。CSVファイルに複数のテストケースを記述してインポートすることで、ロジックを複数の入力パターンで一括評価できる。

対象ユーザーが非エンジニアであることを踏まえ、CSVはExcel・Google Sheetsで直接開いて編集できる形式とする。ユーザーはツールが提供するテンプレートをダウンロードし、Excelで入力を記入して保存したファイルをインポートするだけでよい。

## 10.2 CSVファイル仕様

### 10.2.1 エンコーディングと区切り文字

| 項目 | 値 |
| --- | --- |
| 文字エンコーディング | UTF-8（BOM付き） |
| 区切り文字 | カンマ `,` |
| 改行コード | CRLF / LF どちらも受け付ける |
| クォート | RFC 4180 準拠（値にカンマや改行を含む場合はダブルクォートで囲む） |

UTF-8 BOM付きとすることで、Excelで開いた際に文字化けが発生しない。

### 10.2.2 ヘッダー行

1行目はヘッダー行であり、各列の意味を定義する。

| 列の種類 | ヘッダーの値 | 意味 |
| --- | --- | --- |
| ケース名列 | `ケース名` | テストケースの名前（省略可） |
| 入力値列 | フィールド名（例: `年齢`、`会員種別`） | 対応するフィールドへの入力値 |
| 期待値列 | `期待:<出力列名>`（例: `期待:割引率`） | 評価結果と突き合わせる期待値（省略可） |

- `ケース名` 列は省略可能。存在しない場合は `ケース1`、`ケース2`... と自動付番する
- フィールド名はロジックのフィールド定義の**名前**（表示名）と一致させる
- 一致するフィールド名が存在しない列は**無視する**（エラーにはしない）
- 期待値列は0列以上設定可能（省略した場合は期待値なしの評価のみ実施）

### 10.2.3 データ行

2行目以降がテストケースのデータ行となる。

| フィールド型 | 入力値の書式 | 例 |
| --- | --- | --- |
| `string` | 任意のテキスト | `東京` |
| `number` | 数値文字列 | `25` |
| `bool` | `true` または `false` | `true` |
| `enum` | enum値の文字列 | `premium` |
| `date` | `YYYY-MM-DD` | `2026-12-31` |
| `datetime` | `YYYY-MM-DDTHH:mm:ss` | `2026-12-31T23:59:59` |

- セルが空の場合は**未入力**として扱い、`null` として評価する（[05_evaluation.md §5.5](05_evaluation.md) の `coerce` と同じ挙動）
- 型変換に失敗した値（例: 数値フィールドに `abc` を入力）も `null` として扱う
- 期待値列が空の場合は、そのケースの該当出力列の期待値なしとして扱う（`-` 表示）

### 10.2.4 ファイル例

```csv
ケース名,年齢,会員種別,有効期限,期待:割引率,期待:適用プラン
通常の成人会員,25,premium,2026-12-31,20,standard
未成年の無料会員,15,free,,,
期待値なしのケース,40,premium,,,
```

## 10.3 テンプレートCSVのダウンロード

「テンプレートをダウンロード」ボタンを押すと、現在のロジックのフィールド定義と出力列定義に基づいたCSVテンプレートをダウンロードする。

**テンプレートの構成:**

- ヘッダー行: `ケース名` + 全フィールド名 + 全出力列に対応する `期待:<出力列名>`
- データ行: 空行を1行追加（記入開始の目印）
- ファイル名: `{ロジック名}_テストケース.csv`

例（フィールドが「年齢」「会員種別」「有効期限」、出力列が「割引率」「適用プラン」のロジックの場合）:

```csv
ケース名,年齢,会員種別,有効期限,期待:割引率,期待:適用プラン
,,,,,
```

ユーザーはこのファイルをExcelやGoogle Sheetsで開き、行を追記してから保存・インポートする。

## 10.4 UI設計

### 10.4.1 評価パネルのタブ切り替え

現在の評価パネルの上部にタブを追加し、「単一評価」と「バッチ評価」を切り替えられるようにする。

```
┌──────────────────────────────────────┐
│ 評価                                 │
│ [単一評価]  [バッチ評価]             │
└──────────────────────────────────────┘
```

タブの切り替えはそれぞれの状態（入力値・結果）に影響しない。単一評価の入力値を保持したままバッチタブに移動でき、戻っても入力値が消えない。

### 10.4.2 バッチ評価タブのレイアウト

```
┌──────────────────────────────────────────────────┐
│ バッチ評価                                       │
│                                                  │
│  [CSVを読み込む]  [テンプレートをダウンロード]   │
│                                                  │
│  読み込み済み: 審査テスト.csv（3件）             │
│                                                  │
│  [すべて評価実行]  [クリア]                      │
│                                                  │
│  合計 3件  ✓ マッチ 2件  ✗ 不一致 1件           │
│  期待値あり 2件  Pass 1件  Fail 1件              │
│                                                  │
│  ┌────┬──────────────┬────────────┬──────────┐  │
│  │ #  │ ケース名     │ 結果       │ 期待値   │  │
│  ├────┼──────────────┼────────────┼──────────┤  │
│  │ 1  │ 通常会員     │ ✓ マッチ  │ ✓ Pass   │  │
│  │ 2  │ 未成年       │ ✗ 不一致  │ -        │  │
│  │ 3  │ プレミアム   │ ✓ マッチ  │ ✗ Fail   │  │
│  └────┴──────────────┴────────────┴──────────┘  │
│  行をクリックするとトレースを表示                │
└──────────────────────────────────────────────────┘
```

### 10.4.3 ケース詳細（トレース展開）

結果一覧の行をクリックすると、その行の下にトレースを展開表示する。表示内容は [09_debug_trace.md §9.1](09_debug_trace.md) の単一評価と同じトレース形式を使用する。同時に展開できるケースは1件とし、別の行をクリックすると切り替わる。

### 10.4.4 サマリー表示の仕様

| 項目 | 定義 |
| --- | --- |
| 合計 | 読み込んだテストケースの総件数 |
| マッチ | `status: "ok"` となったケースの件数 |
| 不一致 | `status: "no_match"` となったケースの件数 |
| 期待値あり | 期待値列に1つ以上値が設定されているケースの件数 |
| Pass | 期待値ありのケースのうち、すべての期待値列が一致したケースの件数 |
| Fail | 期待値ありのケースのうち、1つ以上の期待値列が不一致または `no_match` だったケースの件数 |

## 10.5 期待値の突き合わせ仕様

期待値列（`期待:<出力列名>`）が指定されているケースでは、評価結果の出力値と突き合わせて Pass / Fail を判定する。

| 条件 | 判定 |
| --- | --- |
| 評価が `ok` かつ全期待値列の値が出力値と完全一致（文字列比較） | Pass |
| 評価が `ok` かつ1つ以上の期待値列が不一致 | Fail |
| 評価が `no_match` | Fail（マッチしなかったため出力値が存在しない） |
| 期待値セルが空 | そのケースの該当列は判定対象外（`-` 表示） |

出力値との比較は**文字列の完全一致**とする。前後の空白は比較前にトリムする。

## 10.6 バリデーションとエラー処理

### 10.6.1 ファイル読み込み時のバリデーション

| エラー種別 | 挙動 | ユーザーへの表示 |
| --- | --- | --- |
| CSVとして解析できないファイル | 読み込みを中止 | 「CSVファイルを読み込めませんでした。Excelで作成したCSVファイルを選択してください。」 |
| ヘッダー行が空 | 読み込みを中止 | 「ヘッダー行が空です。テンプレートをダウンロードして作成してください。」 |
| データ行が0件 | 読み込みを中止 | 「テストケースが1件もありません。データ行を追加してください。」 |
| 一致するフィールド名の列が0件 | 警告のみ（読み込みは継続） | 「入力値の列が見つかりませんでした。ヘッダーのフィールド名がロジックのフィールド名と一致しているか確認してください。」 |

### 10.6.2 評価実行時の挙動

- 各ケースは独立して評価する（あるケースが `no_match` になっても次のケースの評価を継続する）
- 評価エンジン（[05_evaluation.md §5.2](05_evaluation.md) の `evaluateTable`）は既存の実装をそのまま使用する
- 全ケースの評価が完了した後に結果一覧を一括表示する
