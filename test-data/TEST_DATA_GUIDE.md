# テストデータ ガイド

ディシジョンテーブルエディタの動作を手動で検証するためのインポート用テストデータ集です。  
各 JSON ファイルをUIの「インポート」機能から読み込み、以下に記載した手順と期待結果を確認してください。

---

## 詳細

### TC-01: 基本フィールド型テスト

**ファイル**: `tc01-basic-field-types.json`

**構成**:
- フィールド: 年齢(number), 氏名(string), 会員フラグ(bool), プラン(enum), 登録日(date), 最終ログイン(datetime)
- テーブル: 1つ（顧客分類テーブル）、5行

**検証項目**:
1. インポートが正常に完了し、フィールド定義パネルに6種のフィールドが表示される
2. 各フィールド型に対応したセルエディタが表示される（numberなら数値入力、boolならセレクト、enumならドロップダウン等）
3. 評価実行で以下の入力・期待出力を確認する

| 入力 | 期待する出力 |
|---|---|
| 年齢=70, 会員フラグ=true, プラン=premium | 分類: シニアプレミアム会員 |
| 年齢=30, 会員フラグ=true, プラン=premium | 分類: プレミアム会員 |
| 年齢=25, 会員フラグ=true, プラン=standard | 分類: 一般会員 |
| 会員フラグ=false | 分類: 未分類（デフォルト行） |

### TC-02: 全演算子テスト

**ファイル**: `tc02-all-operators.json`

**構成**:
- フィールド: スコア(number), メモ(string), 有効フラグ(bool), ステータス(enum), 申請日(date)
- テーブル: 1つ、25行（各演算子を1行ずつ使用）

**検証項目**:
各行は独立した演算子の動作確認。出力列「マッチする入力例」に記載の値を入力してマッチすることを確認する。

| 行 | 演算子 | マッチする入力例 | マッチしない入力例 |
|---|---|---|---|
| r1 | number: = 100 | スコア=100 | スコア=99 |
| r7 | number: between 60〜79 | スコア=60, 70, 79 | スコア=59, 80 |
| r8 | number: null | スコア=（空欄） | スコア=0 |
| r10 | string: contains "エラー" | メモ="エラー発生" | メモ="警告" |
| r11 | string: starts_with "警告" | メモ="警告: 残高不足" | メモ="エラー警告" |
| r13 | string: in [承認, 却下, 保留] | メモ="承認" | メモ="審査中" |
| r17 | bool: null | 有効フラグ=（空欄） | 有効フラグ=false |
| r20 | enum: in [active, pending] | ステータス=active | ステータス=inactive |
| r23 | date: between 2024-01-01〜2024-03-31 | 申請日=2024-02-15 | 申請日=2024-04-01 |

### TC-03: 複数テーブル連鎖（継続参照）

**ファイル**: `tc03-multi-table-chain.json`

**構成**:
- フィールド: 申請種別(enum), 契約年数(number), 延滞歴あり(bool), 解約理由(enum)
- テーブル: 4つ（申請振り分け→新規審査 or 更新審査 or 解約処理）
- DAGグラフ: t1 → t2, t1 → t3, t1 → t4

**検証項目**:
1. DAGグラフビューに4つのノードと継続参照の矢印が表示される
2. 評価トレースに複数ステップが記録される（経由したテーブル名が順に表示される）
3. 以下の入力・期待出力を確認する

| 入力 | 経由テーブル | 期待する出力 |
|---|---|---|
| 申請種別=新規, 延滞歴あり=false | t1 → t2 | 審査結果: 承認 |
| 申請種別=新規, 延滞歴あり=true | t1 → t2 | 審査結果: 審査中 |
| 申請種別=更新, 契約年数=5 | t1 → t3 | 更新処理: 自動更新 — 書類不要 |
| 申請種別=更新, 契約年数=2 | t1 → t3 | 更新処理: 手動更新 |
| 申請種別=解約, 解約理由=価格 | t1 → t4 | 引き止め施策: 割引プランを案内 |
| 申請種別=解約, 解約理由=機能 | t1 → t4 | 引き止め施策: ロードマップを共有 |

### TC-04: 品質チェック — 重複行

**ファイル**: `tc04-quality-duplicates.json`

**構成**:
- フィールド: 顧客ランク(enum), 購入金額(number)
- 6行のうち r1≡r3（全条件一致）、r2≡r4（全条件一致）の重複ペアを含む

**検証項目**:
1. インポート後、テーブルを開くと r1, r2, r3, r4 に「重複」マーカー（警告アイコンまたはハイライト）が表示される
2. r5, r6 には警告が表示されない
3. 品質チェックパネルに「重複行」の警告が列挙される

---

### TC-05: 品質チェック — 到達不能行

**ファイル**: `tc05-quality-unreachable.json`

**構成**:
- フィールド: 地域(enum), 優先度(enum)
- r1（地域=東京、優先度はワイルドカード）が r2, r3（地域=東京 + 優先度指定）を包含
- r4 と r5 が同条件で r5 が到達不能

**検証項目**:
1. r2, r3, r5 に「到達不能」マーカーが表示される
2. r1, r4, r6, r7 には到達不能マーカーが表示されない
3. 実際に評価すると r2, r3 にはマッチせず r1 がマッチする

| 入力 | 期待する出力 |
|---|---|
| 地域=東京, 優先度=high | 担当チーム: 東京チーム全般（r1でマッチ。r2は通過されない） |
| 地域=東京 | 担当チーム: 東京チーム全般（r1でマッチ） |
| 地域=名古屋 | 担当チーム: 名古屋チーム |

### TC-06: 品質チェック — デフォルト行なし

**ファイル**: `tc06-quality-no-default.json`

**構成**:
- フィールド: 商品カテゴリ(enum), 注文金額(number)
- 4行すべてに条件があり、ワイルドカード行（全セル空）がない

**検証項目**:
1. 品質チェックで「デフォルト行なし」警告が表示される
2. 以下の未カバー入力で評価すると `no_match` になる

| 入力（no_matchになるケース） |
|---|
| 商品カテゴリ=衣類 |
| 商品カテゴリ=電化製品, 注文金額=5000（10000未満） |
| 商品カテゴリ=食品, 注文金額=（空欄） |

3. 以下はマッチする（正常ケース）

| 入力 | 期待する出力 |
|---|---|
| 商品カテゴリ=食品, 注文金額=3000 | 送料: 無料, 配送日数: 翌日 |
| 商品カテゴリ=書籍 | 送料: メール便250円 |

### TC-07: 網羅性チェック（enum/bool）

**ファイル**: `tc07-coverage-check.json`

**構成**:
- フィールド: 地域(enum: 東日本/西日本/九州), プラン(enum: ライト/スタンダード/プレミアム), 本人確認済(bool)
- 全組み合わせ: 3 × 3 × 2 = 18通り
- カバーされている組み合わせ: 5行の具体条件 + r6（本人確認済=false）のみ
- 未カバーの組み合わせが複数存在する（九州地区のtrue系、西日本+ライトのtrue など）

**検証項目**:
1. テーブル表示に「未カバーの組み合わせ」セクションが表示される
2. 未カバーとして以下の組み合わせが列挙される（一部例）:
   - 九州 / ライト / true
   - 九州 / スタンダード / true
   - 九州 / プレミアム / true
   - 西日本 / ライト / true
3. 網羅率の数値や未カバー数が表示される

### TC-08: 日付・日時演算子テスト

**ファイル**: `tc08-date-operators.json`

**構成**:
- フィールド: 有効期限(date), 申請日時(datetime), 書類種別(enum)
- テーブル1（有効期限確認）: before_today / today_or_before / after_today / today_or_after / between / < / null
- テーブル2（申請日時確認）: between / >= / null

**検証項目**:

テーブル1（評価実行はエントリーテーブルt1から）:

| 入力 | 期待する出力（実行日により変わる相対演算子に注意） |
|---|---|
| 有効期限=2020-01-01（過去日付） | 有効期限ステータス: 期限切れ |
| 有効期限=（本日の日付）, 書類種別=パスポート | 有効期限ステータス: 本日期限（パスポート） |
| 有効期限=2099-12-31（遠い将来）, 書類種別=パスポート | 有効期限ステータス: 有効（公的書類） |
| 有効期限=2024-06-15 | 有効期限ステータス: 2024年度発行 |
| 有効期限=（空欄） | 有効期限ステータス: 有効期限未入力 |

テーブル2はエントリーテーブルではないため直接評価できないが、tc03等と組み合わせたDAGで参照可能。

### TC-09: 実務シナリオ — 保険金請求ルーティング

**ファイル**: `tc09-real-world-insurance.json`

**構成**:
- フィールド: 請求種別(enum), 請求金額(number), 契約年数(number), 免責期間内(bool), 診断書提出済(bool), 事故発生日(date), 顧客メモ(string)
- テーブル: 3つ（受付 → 高額査定 or 一般医療査定）
- 複数の出力列（受付結果, 担当部門, 査定結果, 支払限度額, 必要書類 等）

**検証項目**:
1. DAGグラフに3ノードの連鎖が表示される
2. 評価トレースで各テーブルの通過経緯が確認できる

| 入力 | 期待する評価経路と出力 |
|---|---|
| 免責期間内=true | 受付結果: 受付不可（t1で終了） |
| 請求種別=死亡, 免責期間内=false, 診断書提出済=false | 査定結果: 書類不備（t1→t2） |
| 請求種別=死亡, 免責期間内=false, 診断書提出済=true, 契約年数=6, 事故発生日=（過去日付） | 査定結果: 支払承認（優良契約者）（t1→t2） |
| 請求種別=医療費, 免責期間内=false, 診断書提出済=true, 請求金額=50000 | 査定結果: 支払承認（t1→t3） |
| 請求種別=医療費, 免責期間内=false, 診断書提出済=true, 請求金額=50000, 顧客メモ=緊急対応 | 査定結果: 即日支払（t1→t3・containsマッチ） |
| 請求種別=医療費, 免責期間内=false, 診断書提出済=true, 請求金額=2000000 | 査定結果: 高額審査（t1→t3） |

### TC-10: 自動修復テスト

**ファイル**: `tc10-auto-repair.json`

**構成**:
- t1 の r2 が存在しないテーブル `t999` を継続参照している（壊れた参照）
- t2 の `outputCols` が空配列（仕様違反: 出力列0件）

**検証項目**:
1. インポート直後に「インポート時に自動修復を行いました」トーストが表示される
2. 修復内容:
   - t1 の r2 の結論が `terminal`（空outputs）に変換されている
   - t2 に出力列「結果」が自動追加されている
3. 修復後は正常に評価・編集ができる

| 入力 | 期待する出力（修復後） |
|---|---|
| カテゴリ=A, 値=150 | t2 の「結果」列に値なし（自動修復された空outputs） |
| カテゴリ=B | 振り分け結果: 空（t999参照がterminal空に変換済み） |
| カテゴリ=C | 振り分け結果: デフォルト |

## 手動検証チェックリスト

各テストデータをインポートした後、以下の共通項目も確認してください。

### インポート・エクスポート
- [ ] JSON ファイルをインポートできる
- [ ] インポート後にエクスポートした JSON が元のファイルと同等の内容を持つ
- [ ] 不正な JSON をインポートするとエラートーストが表示される

### フィールド定義パネル
- [ ] フィールド一覧が正しく表示される
- [ ] enum型フィールドの選択肢が表示・編集できる
- [ ] フィールドタイプに応じたアイコン・ラベルが表示される

### テーブル表示・編集
- [ ] テーブル名のインライン編集ができる
- [ ] 行の追加・削除ができる
- [ ] 条件列の追加・削除ができる
- [ ] セルのドラッグ&ドロップで行の並び替えができる

### 評価（デバッグ）
- [ ] 評価パネルで入力フィールドに値を入力できる
- [ ] 評価結果（outputs）が表示される
- [ ] トレースビューに経由したテーブルと行が表示される
- [ ] no_match の場合にその旨が表示される

### DAGグラフ
- [ ] 継続参照があるロジックでグラフビューにノードと矢印が表示される
- [ ] エントリーテーブルが識別可能な表示になっている
